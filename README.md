# 开车分账｜单机谈判桌游
一款本地单机网页游戏：你与可选数量的电脑玩家（AI 对手）先聊天、谈判与交易，再一起“开车”结算。游戏无需联网，也不需要大模型 API-Key；电脑玩家通过内置策略和对话模板行动。项目采用 NestJS 提供 API，浏览器端为原生 HTML/CSS/JavaScript。
## 游戏规则
### 目标与开局
- 你和 2–5 名电脑玩家组成一桌（总人数 3–6 人）。开局每人获得 **100 代币**，另有一辆公共车辆，初始价值 **120 代币**。
- 每局共 **3 个谈判回合**。玩家可以在回合聊天、发起交易；第三回合结束后可提前开车，或让回合走完再统一结算。
- 电脑玩家数量可在新局设置中选择（2–5 名）。本原型采用本地策略 AI，不会向外部服务发送数据。
### 公开聊天与私聊
- 公开消息全桌可见；私聊仅发送者与指定接收者可见。
- 消息用于角色扮演和谈判，不直接改变代币或契约。游戏不设自由文本判定惩罚。
- 电脑玩家会按自身性格、资金和已签协议作出回应；对话是策略提示，不构成强制契约。
### 交易与承诺
- 可向任意玩家提出一次性代币转账，填写金额与简短备注。电脑玩家会按概率接受/拒绝；玩家发来的提案由你在交易卡片中接受或拒绝。接受后立即转账；拒绝或未处理不产生变化。
- 转账金额必须为正整数，且不能超过付款方当前余额。交易不能撤销；双方可在聊天中协商，但只有接受交易按钮具有规则效力。
- 交易可以发生在开车前，影响最终分账；所有玩家的资产变化记录在交易日志中。
### 开车与结算
- 任一玩家均可在所有谈判回合结束前选择“开车”，立即结束谈判并结算；否则在第三回合结束时自动结算。
- 结算池 = 公共车辆价值 + 全体玩家结算时的代币总额。车辆基础价值为 120；每完成一个谈判回合，车辆价值增加 15（最多增加 45）。
- 每名玩家的分配权重 = 1 + floor(该玩家结算时余额 / 50)。结算池按权重比例分配，使用最大余数法将整数代币分完，确保总分配额严格等于结算池。
- 本局以最终所得代币最高者获胜；并列则共享胜利。结束页展示每人的分配、权重、交易和获胜者。
## 运行
需要 Node.js 20+ 与 npm。
```bash
npm install
npm run start:dev
```
浏览器打开 `http://localhost:3000`。也可用 `npm run build && npm start` 以生产模式运行。NestJS API 入口为 `GET /api/game/rules`；游戏状态和回合逻辑目前在浏览器本地运行，因此无需数据库或账户。
## 项目结构
```text
src/                 NestJS 服务端入口与规则 API
public/              单页游戏前端（本地状态、聊天、交易与结算）
README.md            规则与运行说明
```
## 可选扩展
后续可添加持久化存档、可配置规则、更多 AI 性格或联机房间。若希望接入大模型以生成更自然的对话，需要配置服务端 API-Key；当前原型不需要，也不应把密钥放在浏览器端。
